## 一、变量：给内存起个名字

### 1.1 变量的本质

上一课讲的 `int`、`double` 是**类型**——它规定"这块内存怎么解释、占几个字节"。
但类型本身存不了东西，真正存数据的是**变量**。

```cpp
int age = 18;
```

这行代码干了两件事：

1. 在内存里**划出一块**足够放下 int 的空间（4 字节）
2. 给这块空间**起了个名字**叫 `age`，并写进去 18

> **一句话：变量就是"一段内存空间的名字"。**
> CPU 只认地址，不认名字。名字是给人看的。

**实测证据**——用 `&` 把地址打出来：

```cpp
int value = 42;
cout << &value;   // 00000062E876F7F0
```

`&value` 就是这个变量在内存中的地址（16 进制）。同一个程序每次运行地址都可能不同。

### 1.2 定义的语法

```cpp
数据类型  变量名  =  初始值;
   ↑        ↑         ↑
  三要素，前两个必须有，初值建议也给上
```

```cpp
int      age    = 18;
double   price  = 9.9;
char     grade  = 'A';
bool     passed = true;
string   name   = "宝宝";
```

### 1.3 三种初始化写法

| 写法 | 名称 | 说明 |
| --- | --- | --- |
| `int a = 10;` | 赋值初始化 | 最常用、最直观，从 C 继承来 |
| `int b(20);` | 括号初始化 | 也是从 C 继承的，容易和函数声明混淆 |
| `int c{30};` | **列表初始化** | C++11 新增，**推荐**，下面详说 |
| `int d{};` | 列表初始化为 0 | 不写值就明确初始化成 0 |

**为什么推荐列表初始化 `{}`？** 因为它会**拦住窄化转换**：

```cpp
int e{3.14};   // ❌ 编译报错！double 塞进 int 会丢精度，编译器直接拦住
int e = 3.14;  // ⚠️ 只给个警告，照样编过，e 变成 3
```

实测印证：赋值初始化的版本编译通过，运行时 `e = 3`（小数被截断，**不是四舍五入**）。
用 `{}` 写的话，这个问题在编译期就被揪出来了。

> 📌 **养成的习惯**：能用 `{}` 就用 `{}`。多打两个字符，少踩一堆坑。

### 1.4 「初始化」和「赋值」不是一回事

```cpp
int init = 100;   // ← 初始化：变量"出生"时就带上了值
init = 200;       // ← 赋值：变量已经存在，把新值覆盖上去
```

现阶段看不出区别（结果都是 200），但概念要分清：

- **初始化**：一辈子只发生一次，跟着变量出生
- **赋值**：可以发生无数次

后面学到「引用」和「const」时，这个区别会变成硬性规则——引用必须初始化，const 必须初始化且不能赋值。

### 1.5 作用域初步

变量只在它所在的 `{}` 里活着：

```cpp
int x = 1;
{
    int x = 2;        // 另一个 x，和外层没关系（暂时"盖住"了外层）
    cout << x;        // 2
}
cout << x;            // 1  ← 内层那个已经销毁了
```

实测输出：
```
内层 x = 2（内层的，暂时盖住了外层）
外层 x = 1（内层那个已经没了）
```

> 这种「内层同名变量盖住外层」的现象叫 **shadowing（遮蔽）**。
> 能编过，但**强烈不建议这么写**——很容易看错。换个名字就好。

## 二、常量：值不能改的量

### 2.1 三种"常量"

| 类型 | 长什么样 | 说明 |
| --- | --- | --- |
| **字面常量** | `3.1415926`、`100`、`'A'` | 直接写在代码里的值，没名字 |
| **`#define` 宏常量** | `#define PI 3.1415926` | C 语言留下的老方式 |
| **`const` 常量** | `const double PI = 3.1415926;` | **C++ 推荐方式** |

三种都能用，实际项目里 **首选 `const`**，原因见 2.4。

### 2.2 `#define` 宏常量

```cpp
#include <iostream>
using namespace std;

#define PI 3.1415926      // ← 写在函数外面，文件开头
#define MAX_SCORE 100

int main() {
    cout << PI * 2 * 2;   // 用起来和普通变量一样
}
```

**四个注意点：**

1. **结尾不写分号**——它不是语句，是"文本替换"指令
2. 习惯**常量名全大写**，用下划线分词（`MAX_SCORE`）
3. 必须写在**函数外面**（它不属于任何函数）
4. 一旦定义，后面的代码都能用

### 2.3 `const` 常量

```cpp
const double PI2 = 3.1415926;      // 写在文件里、函数里都行
const int DAYS_IN_WEEK = 7;
```

`const` 的意思是"**只读**"——这个变量初始化之后不能再被赋值：

```cpp
const int a = 10;
a = 20;        // ❌ error C3892: 不能给常量赋值
```

> 名字习惯写全大写，但这不是强制的。`const` 只是让编译器帮你把关，
> **任何试图修改它的代码都会在编译期被拦下来**——这就是用常量的最大价值：
> 错误提前到编译期，而不是运行时才发现。

### 2.4 `#define` vs `const`：本质完全不同

这是本课**最值得深挖**的地方。很多教程只说"两种都行"，但它们的机制差别很大。

#### 区别一：`#define` 是纯文本替换

`#define` 在**预处理阶段**就被替换掉了，编译器根本看不到它。它是把一串文字**原样贴**进去。

看这个实测的坑：

```cpp
#define BAD_VALUE 1 + 2
const int GOOD_VALUE = 1 + 2;

cout << BAD_VALUE  * 3;   // 输出 7  ← 期望 9！
cout << GOOD_VALUE * 3;   // 输出 9  ← 正确
```

**为什么？** 因为 `BAD_VALUE * 3` 在预处理后变成了：

```cpp
1 + 2 * 3      // 先算乘法 → 1 + 6 = 7 ❌
```

`#define` 只是把 `1 + 2` 这串字贴进去，**不带括号、不看优先级**。
要躲这个坑，得自己加括号 `#define BAD_VALUE (1 + 2)`——但既然到处要防这个坑，为什么不直接用 `const`？

#### 区别二：`#define` 不遵守作用域

```cpp
{
    #define INNER 999
}
cout << INNER;    // 实测输出 999 —— 出了花括号它居然还活着！
```

`#define` 从定义那一行起，**一直有效到文件结尾**（除非 `#undef`）。
它完全无视 `{}`，因为预处理阶段根本没有"作用域"这个概念。

而 `const` 严格遵守作用域：

```cpp
{
    const int inner = 888;
}
// cout << inner;   // ❌ 报错：未声明的标识符 ✅ 这才是正常行为
```

#### 区别三：`#define` 没有类型

```cpp
#define HUNDRED 100
sizeof(HUNDRED);   // 4 —— 它没有自己的类型，是按字面量 100 的 int 算出来的
```

没有类型意味着**不参与类型检查**，也就少了编译器帮你把关的机会。
`const int` 则是货真价实的 `int`，该有的检查一个不少。

#### 总结对照表

| | `#define` 宏常量 | `const` 常量 |
| --- | :---: | :---: |
| 处理阶段 | 预处理（编译前） | 编译期 |
| 机制 | 纯文本替换 | 真正的只读变量 |
| 有类型吗 | ❌ 没有 | ✅ 有 |
| 参与类型检查 | ❌ | ✅ |
| 遵守作用域 | ❌ 无视 `{}` | ✅ 严格遵守 |
| 调试器里能看到吗 | ❌ 符号表里没有 | ✅ 能看到 |
| 会踩优先级坑 | ✅ 容易 | ❌ 不会 |
| 结论 | 知道就行，尽量不用 | **推荐** |

> 老代码和很多教程还在用 `#define`，所以**必须认识它**。
> 但自己写代码时，**用 `const`**。

### 2.5 实战意义：消灭「魔法数字」

这是常量真正的用武之地。

**❌ 反面写法：**

```cpp
double area = 3.1415926 * r * r;
int scores[5] = {...};
for (int i = 0; i < 5; i++) { ... }
```

问题在哪？`3.1415926` 是什么、`5` 是什么，**得过一个月自己都忘了**；
要把数组改成 10 个元素，得满代码找 `5`，漏一个就出 bug。
这种没名字的数字叫 **魔法数字（magic number）**。

**✅ 正面写法：**

```cpp
const double PI = 3.1415926;
const int SIZE = 5;

double area = PI * r * r;
int scores[SIZE] = {90, 85, 77, 92, 88};
for (int i = 0; i < SIZE; i++) { ... }
```

好处是**三件事同时解决**：

1. **自解释**——`PI` 比 `3.1415926` 一眼就懂，名字就是文档
2. **改一处**——`SIZE` 从 5 改成 10，只动一行，数组长度和循环上界自动同步
3. **防手滑**——不会因为某处忘了改而写出 `for (i = 0; i < 5; i++)` 配 `int scores[10]` 这种半吊子代码

实测输出印证了第 2 点——数组和循环共用 `SIZE`，改一处两边一起变。

> 📌 **一条能用在所有语言里的原则**：
> 代码里出现第二次的"有含义的数字"，就该给它起个名字。

## 四、今日小结

**记住了什么**

1. **变量 = 一段内存的名字**。`&变量` 能看到它的地址，`sizeof(变量)` 看它占多大
2. 定义语法：`类型 名字 = 初值;`，初始化推荐用 `{}`（能拦住窄化转换）
3. **初始化只发生一次，赋值可以无数次**——后面学引用/const 时这是硬规则
4. 常量三种写法，**首选 `const`**；`#define` 认识但少用
5. `#define` 是**预处理文本替换**：没有类型、无视作用域、不看优先级
6. 用常量**消灭魔法数字**——代码自解释 + 改一处生效

**踩到的坑**

| 坑 | 症状 | 记住 |
| --- | --- | --- |
| 局部变量不初始化 | 值是随机垃圾值，编译器只给 warning C4700 | 定义就给初值，或写 `{}` |
| 宏不带括号 | `#define V 1+2`，`V*3` 得到 7 不是 9 | 别用宏，用 `const` |
| 宏泄漏作用域 | 出了 `{}` 还能用 | 预处理阶段没有作用域概念 |
| 赋值初始化截断 | `int e = 3.14` 只警告不报错，e 变成 3 | 用 `{}` 初始化 |

**待办 / 疑问**

- [ ] `const` 和 `constexpr` 有什么区别？（C++11 引入的 `constexpr` 是编译期求值，后面会遇到）
- [ ] 全局变量和局部变量的默认初值为什么不一样？（全局默认 0，局部是垃圾值——和内存分区有关）
- [ ] `string` 的 `sizeof` 是 32 字节，但字符串明显可以更长，它是怎么存的？（后面学类和动态内存就懂了）
