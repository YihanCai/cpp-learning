## 一、算术运算符

### 1.1 五个基本功

| 运算符 | 名称 | 例子 | 结果 |
| :---: | --- | --- | :---: |
| `+` | 加 | `10 + 3` | 13 |
| `-` | 减 | `10 - 3` | 7 |
| `*` | 乘 | `10 * 3` | 30 |
| `/` | 除 | `10 / 3` | **3** ← 注意！ |
| `%` | 取模（求余） | `10 % 3` | 1 |

### 1.2 【重点】整数除法会截断

这是新手最常翻的车：

```cpp
10 / 3     // 3      不是 3.33
10.0 / 3   // 3.33333
10 / 3.0   // 3.33333
```

**规则：两个整数相除，结果还是整数，小数部分直接扔掉（不是四舍五入）。**

想得到小数，**必须有一个操作数是浮点**：

```cpp
int x = 10, y = 3;
x / y                 // 3        两边都是 int，整数除法
(double)x / y         // 3.33333  转一个就行
x / (double)y         // 3.33333  转哪个都一样
```

> 实测还有一个细节：`10.0 / 3` 打印出来是 `3.33333` 而不是更长的数——
> 因为 `cout` **默认只显示 6 位有效数字**。要更多位得用 `setprecision()`。

### 1.3 【重点】取模 `%`

```cpp
10 % 3   // 1
10 % 5   // 0   ← 能整除就是 0
3 % 10   // 3   ← 小的模大的，还是自己
```

**负数取模的符号规则**（C++11 起明确规定，但很多人不知道）：

> **结果的符号跟「被除数」走，不跟除数走。**

实测：

| 表达式 | 结果 |
| --- | :---: |
| `7 % 3` | 1 |
| `-7 % 3` | **-1** |
| `7 % -3` | **1** |
| `-7 % -3` | -1 |

⚠️ 这条规则**各语言不一样**（Python 里 `-7 % 3` 是 `2`）。写跨语言代码时要特别小心。

**`%` 只能用于整数**，浮点要取余得用 `fmod()`：

```cpp
// 10.0 % 3        // ❌ 编译报错
fmod(10.5, 3.0)    // 1.5  ← 需要 #include <cmath>
```

### 1.4 【重点】前置 `++i` 和后置 `i++`

```cpp
int i = 5;
int r1 = i++;   // r1 = 5, i = 6   后置：先把自己的值交出去，再自增
int j = 5;
int r2 = ++j;   // r2 = 6, j = 6   前置：先自增，再把新值交出去
```

**记忆方法：看 `+` 的位置**

- `i++` 的 `+` 在后面 → **先取值，后加**
- `++i` 的 `+` 在前面 → **先加，后取值**

**关键：单独成行时，`i++;` 和 `++i;` 完全等价**，区别只在被赋值或参与运算时才体现。

实测对比（循环里输出）：

```
k++ 输出：0 1 2     ← 先输出当前值再自增
++p 输出：1 2 3     ← 先自增再输出
```

> 📌 进阶：对**自定义类型**（比如迭代器）来说，`i++` 因为要保留一份旧值再返回，会比 `++i` 多一次拷贝。
> 所以 C++ 圈有个习惯：**循环里能用 `++i` 就用 `++i`**。对 `int` 无所谓，对迭代器有实际性能差别。

## 二、赋值运算符

### 2.1 复合赋值

| 写法 | 等价于 | `a = 10` 时的结果 |
| --- | --- | :---: |
| `a += 5` | `a = a + 5` | 15 |
| `a -= 3` | `a = a - 3` | 12 |
| `a *= 2` | `a = a * 2` | 24 |
| `a /= 4` | `a = a / 4` | 6（整数除法） |
| `a %= 3` | `a = a % 3` | 0 |

**复合赋值的两个好处：**

1. 写得短
2. 左边**只求值一次**——如果左边是个复杂表达式（带函数调用等副作用），这点很重要

### 2.2 无符号变量的 `-=` 陷阱

```cpp
unsigned int u = 0;
u -= 1;      // 不是 -1，而是 4294967295  ← 回绕到最大值
```

实测输出就是这个值。无符号类型没有负数，减过头会绕回上限。
**所以无符号变量做减法要格外小心。**

## 三、比较运算符

### 3.1 六个比较运算符

| 运算符 | 含义 |
| :---: | --- |
| `==` | 相等 |
| `!=` | 不相等 |
| `>` | 大于 |
| `<` | 小于 |
| `>=` | 大于等于 |
| `<=` | 小于等于 |

**比较的结果是 `bool`（真/假）**，默认打印成 `1`/`0`。想看 `true`/`false`：

```cpp
cout << boolalpha << (x == y);   // 输出 true / false
cout << noboolalpha;             // 恢复成 1 / 0
```

### 3.2 【重点】`=` 和 `==` 别混

```cpp
=   是【赋值】——  把右边的值放进左边
==  是【比较】——  判断两边是否相等
```

**最经典的翻车：**

```cpp
int flag = 0;
if (flag = 1) { ... }    // ⚠️ 这是赋值！flag 被赋成 1，条件永远为真
if (flag == 1) { ... }   // ✅ 这才是比较
```

实测确认：`if (flag = 1)` **真的走进了 if 分支**。
编译器通常只给个警告（甚至不报），运行时逻辑就错了。

**防御技巧**——把常量写到左边：

```cpp
if (1 == flag) { ... }   // 写漏一个 = 变成 1 = flag → 编译期直接报错
// error C2106: “=”: 左操作数必须为左值
```

写错会**编译不过**，而不是静默出错。这是个很实用的小习惯。

### 3.3 浮点数不能直接用 `==`

```cpp
double a = 0.1, b = 0.2;
(a + b) == 0.3        // false！
```

原因在 Day 01 讲过：`0.1` 和 `0.2` 在二进制浮点里存的是近似值，
`a + b` 实际是 `0.30000000000000004`。

**正确写法**——比较差值是否小于一个极小阈值：

```cpp
const double EPS = 1e-9;
fabs((a + b) - 0.3) < EPS    // true
```

## 四、逻辑运算符

### 4.1 三个运算符

| 运算符 | 名称 | 规则 |
| :---: | --- | --- |
| `&&` | 逻辑与 | 两个都真才是真 |
| `\|\|` | 逻辑或 | 有一个真就是真 |
| `!` | 逻辑非 | 真变假，假变真 |

**"非 0 即真"**——用整数当条件时，0 是假，其它（包括负数）都是真：

```cpp
5 && 1    // true
5 && 0    // false    ← 0 当假
-1 && 1   // true     ← 负数也是真
!!5       // true     ← 双非可以把任意值压成 bool
```

### 4.2 【重点】短路求值

> **`&&` 左边已经为假 → 右边根本不执行**
> **`||` 左边已经为真 → 右边根本不执行**

我写了个带计数副作用的函数来验证，实测调用次数：

| 表达式 | 结果 | 右侧被调用次数 |
| --- | :---: | :---: |
| `false && sideEffect()` | false | **0** ← 没执行 |
| `true \|\| sideEffect()` | true | **0** ← 没执行 |
| `true && sideEffect()` | true | 1 ← 执行了 |
| `false \|\| sideEffect()` | true | 1 ← 执行了 |

### 4.3 短路的实战用途：用顺序保护后面的操作

这是短路最有价值的地方——**把"安全检查"放在前面**：

```cpp
int arr[5] = {10, 20, 30, 40, 50};
int index = 10;              // 越界

// ❌ 危险：先访问再判断，越界就完了
if (arr[index] > 0 && index < 5) { }

// ✅ 正确：范围判断放前面，越界时右边根本不执行
if (index < 5 && arr[index] > 0) { }
```

实测：`index = 10` 时因为短路，`arr[10]` **从未被访问**，程序安全。

同样的技巧可以防除零：

```cpp
int divisor = 0;
if (divisor != 0 && 100 / divisor > 5) { }   // 短路跳过了除法，避免崩溃
```

> 📌 **记住这个模式**：`先判断合法性 && 再使用`。这是 C/C++ 里的标准防御写法。

## 五、三目运算符

### 5.1 基本用法

```
条件 ? 条件为真时的值 : 条件为假时的值
```

```cpp
int a = 10, b = 20;
int maxVal = (a > b) ? a : b;                    // 20
string result = (a % 2 == 0) ? "偶数" : "奇数";   // "偶数"
```

### 5.2 【C++ 特色】三目运算的结果是**引用**，可以当左值

这一点是 C++ 和 C 的重要区别：

```cpp
int p = 1, q = 2;
(p > q ? p : q) = 100;      // ✅ C++ 合法，C 语言里会编译报错
// 结果：p = 1（没变），q = 100（被改了）
```

**原理**：三目运算符返回的是一个**引用**（可以理解为"变量本身"），不是值的副本。
所以能对它赋值——赋给谁取决于条件选中了哪个变量。

> 实测确认：`q` 被改成 100，`p` 没动（因为 `q > p`，选中的是 `q`）。
> 面试题里常见，实际写代码**别这么用**，可读性太差。

**可读性提醒**：三目别嵌套超过两层，三层就该改写成 `if-else`。

## 六、运算符优先级

### 6.1 常用优先级（从高到低）

| 优先级 | 运算符 | 结合方向 |
| :---: | --- | --- |
| 1 | `()` `[]` `.` `->` `++` `--`（后置） | 从左到右 |
| 2 | `!` `~` `++` `--`（前置） 一元 `+` `-` `(类型)` `*` `&` `sizeof` | 从右到左 |
| 3 | `*` `/` `%` | 从左到右 |
| 4 | `+` `-` | 从左到右 |
| 5 | `<<` `>>` | 从左到右 |
| 6 | `<` `<=` `>` `>=` | 从左到右 |
| 7 | `==` `!=` | 从左到右 |
| 8 | `&` | 从左到右 |
| 9 | `^` | 从左到右 |
| 10 | `\|` | 从左到右 |
| 11 | `&&` | 从左到右 |
| 12 | `\|\|` | 从左到右 |
| 13 | `?:` | 从右到左 |
| 14 | `=` `+=` `-=` 等赋值 | 从右到左 |
| 15 | `,` | 从左到右 |

### 6.2 三个反直觉的实测案例

这三个我都在编译器上跑过，**`/W3` 会给出警告**：

#### 案例一：`+` 的优先级**高于** `<<`

```cpp
1 << 2 + 3      // 结果是 32，不是 7！
```

因为实际算的是 `1 << (2 + 3)` = `1 << 5` = 32。
想要 7 得写 `(1 << 2) + 3`。

#### 案例二：`==` 的优先级**高于** `&`

```cpp
int flags = 6, mask = 4;
flags & mask == 4     // 结果是 0，你以为应该是 1
```

实际算的是 `flags & (mask == 4)` → `mask == 4` 得 `true`(1) → `6 & 1` = 0。
正确写法：`(flags & mask) == 4`。

#### 案例三：逻辑运算符之间 `!` > `&&` > `||`

```cpp
true || false && false     // true
```

实际是 `true || (false && false)` = `true`。
不是 `(true || false) && false` = `false`。

### 6.3 结论

**优先级记不住就别硬记，拿不准就加括号。**

加括号不丢人，出 bug 才丢人。而且加了括号的可读性明显更好——
下次看代码的人（包括三个月后的你自己）不用去查优先级表。

这是做这一课代码时挖出来的，跟运算符直接相关，**很重要**。

**MSVC 默认只开 `/W1`**（很低），上面那三个优先级问题**一个都不报**。
我实测对比了同一份 `06_pitfalls.cpp`：

| 警告等级 | 警告数 | 报出了什么 |
| :---: | :---: | --- |
| 默认（`/W1`） | 0 | 什么都看不到 |
| `/W3` | **3** | C4554（`<<` 优先级可疑）、C4554（`&` 优先级可疑）、C4018（有符号/无符号不匹配） |
| `/W4` | 8 | 在 `/W3` 基础上多了 5 条 C4189（变量声明了没用到） |

**看到区别了吗？默认等级把真正危险的东西全藏了。**

  `/W3` 是实用和清爽之间的平衡点。

## 九、今日小结

**记住了什么**

1. **整数除法会截断**，想要小数必须有浮点参与
2. **`%` 结果的符号跟被除数走**，且各语言规则不同
3. **`i++` 先取值后加，`++i` 先加后取值**；单独成行时等价
4. **`=` 是赋值，`==` 是比较**——把常量写左边可以防错
5. **短路求值**：`&&` 左假不执行右，`||` 左真不执行右；用它做"先判断后使用"的防御
6. **三目运算符在 C++ 里返回引用**，可以当左值（C 语言不行）
7. **优先级拿不准就加括号**
8. **MSVC 默认 `/W1` 太宽松**，要用 `/W3` 才看得到优先级和符号不匹配的问题

**踩到的坑**

| 坑 | 症状 | 正解 |
| --- | --- | --- |
| 整数除法 | `10/3` 得 3 而不是 3.33 | 让一边变成浮点 |
| 负数取模 | `-7%3` 得 -1，跟 Python 不一样 | 记住符号跟被除数 |
| 无符号减过头 | `0u - 1` 得 4294967295 | 无符号少用减法 |
| `=` 写成 `==`（或反过来） | 条件永远为真 | 常量写左边 |
| 浮点 `==` | `0.1+0.2 == 0.3` 是 false | 用 EPS 阈值比较 |
| 整数除零 | 程序直接崩溃，退出码 0xC0000094 | 除法前判断除数 |
| `<<` 和 `+` 混用 | `1<<2+3` 得 32 不是 7 | 加括号 |
| `++` 混在一个表达式里 | 未定义行为，实测 `i++ + ++i` = 12 | 拆开写 |

**待办 / 疑问**

- [ ] `%` 和 `/` 对负数为什么这么定？（C++11 明确了"向零取整"的规则，之前是未定义的）
- [ ] 短路求值会不会影响性能？（会——所以别在 `&&` 右边放"必须执行"的函数调用）
- [ ] 为什么无符号类型还要存在？它有什么实际好处？（数组下标、位运算、`size_t`）
